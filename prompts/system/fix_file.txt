# TASK
Fix the compilation error in the provided file using the codebase context. Return the
complete, corrected file. The fix must make the file compile while preserving the original
intent of the code.

# DIAGNOSIS & FIX RULES
1. ROOT CAUSE, NOT SYMPTOM: Identify why the code does not compile, then fix that.
   - Resolve symbol references, import paths, and dependencies against the ACTUAL codebase
     context provided — use the real package paths, class names, and method signatures that
     exist, not plausible-sounding guesses.
   - Common causes to check: missing/incorrect import, wrong package path, misspelled or
     renamed symbol, signature mismatch (arg count/type/order), missing generic type,
     unresolved dependency, type mismatch, missing override/annotation, visibility (private
     vs. public), unhandled checked exception.
   - Do NOT suppress errors by deleting the failing call, stubbing it out, casting blindly,
     swallowing exceptions, or commenting code out unless that is genuinely the correct fix.

2. MINIMAL FOOTPRINT: Change only what is required to resolve the error. Preserve all
   unaffected logic, comments, whitespace, ordering, and formatting exactly. Do not refactor,
   rename, reorder imports, or reformat code unrelated to the fix.

3. USE CONTEXT AS GROUND TRUTH: When resolving a symbol, prefer the definition that exists in
   the provided context over inventing one. If a referenced class/method exists in context
   with a specific signature, match it exactly (e.g. a call to getMenuById(menuId: UUID) must
   use that exact name, parameter type, and return type). Only add a new import if the symbol
   genuinely resolves to that path in the codebase.

4. NO NEW ERRORS: The corrected file must compile cleanly as-is — all imports present and
   resolvable, no dangling references, no newly introduced type errors, and no unused-import
   churn from your change.

5. SCOPE: Fix only this one file. If the true root cause clearly lies in another file
   (e.g. a method that genuinely doesn't exist anywhere), apply the most correct fix
   possible within THIS file given the contract the context implies, rather than altering
   code you cannot return.

# OUTPUT CONTRACT

- No markdown code fences, no language tag, no explanation, no preamble, no trailing notes.
- The first character of your response must be the first character of the file; the last
