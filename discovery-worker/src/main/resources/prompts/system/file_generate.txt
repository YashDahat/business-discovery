# TYPESCRIPT / REACT 19 CONSTRAINTS (TS/TSX files only — every rule fixes a recurring build breaker)
1. NEVER annotate return types or props as JSX.Element — the global JSX namespace does not
   exist under React 19's jsx-runtime. Let component return types be INFERRED; for props that
   accept markup use React.ReactNode. If a JSX type is truly unavoidable, the file must start
   with: import type { JSX } from 'react'
2. TANSTACK QUERY v5 API ONLY (v4 idioms do not compile):
   - useQuery({ queryKey: ['trainers'], queryFn: fetchTrainers })  — OBJECT form; positional
     useQuery(['trainers'], fetchTrainers) is a compile error in v5.
   - Mutations expose isPending — mutation.isLoading DOES NOT EXIST on useMutation results.
   - useMutation({ mutationFn: createTrainer, onSuccess: ... }) — object form here too.
3. ZOD NUMERIC FORM FIELDS: HTML inputs yield strings — use z.coerce.number() (NOT z.number())
   for any numeric field bound to an <input>, or the zodResolver output type will not match
   the DTO interface and the resolver assignment fails to compile.
4. TYPE RE-EXPORTS: isolatedModules is on — re-exporting a type requires
   export type { Foo } from './bar'  (a plain export { Foo } fails to compile).
5. BOOLEAN JSX ATTRIBUTES: allowFullScreen, disabled, checked take booleans —
   allowFullScreen={true} or bare allowFullScreen, never allowFullScreen="true".
6. ROUTER-HOOK PROVIDER ORDER: any context/provider whose code calls a router hook
   (useNavigate, useLocation, useParams — e.g. AuthContext calling useNavigate) MUST render
   INSIDE <BrowserRouter>. In App.tsx the nesting is exactly:
     <BrowserRouter> <QueryClientProvider> <AuthProvider> <Routes>…</Routes> </AuthProvider> </QueryClientProvider> </BrowserRouter>
   Placing AuthProvider outside BrowserRouter throws "useNavigate() may be used only in the
   context of a <Router>" at runtime and renders a blank page.
7. API TYPES AND SERVICES ARE PRE-GENERATED GROUND TRUTH: frontend/src/types/<domain>.ts
   and frontend/src/services/<domain>Service.ts are DERIVED from the backend contract and
   already exist — NEVER generate or modify them (like @/components/ui files). Their real
   content appears in your dependency context: import the exact exported interfaces and
   service functions shown there. NEVER call axios/apiClient directly from pages, hooks,
   or components — always call the generated service functions. Frontend-only types that
   have no backend counterpart (cart state, form view-models) go in
   frontend/src/types/local/<name>.ts.
