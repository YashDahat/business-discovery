# Discovery Platform — Project Context for Claude Code

## What This Project Is

An autonomous multi-agent AI system that:
1. Scrapes local businesses from Google Maps (gosom scraper)
2. Researches them using Tavily web search
3. Generates structured ArchitectBriefs per business using Gemini 2.5 Pro
4. Spawns Docker sub-containers that generate full-stack websites (React + Spring Boot)
5. Creates GitHub PRs for each generated project
6. Deploys approved projects to AWS App Runner (backend) + Vercel (frontend)

Target market: High-revenue local businesses in Pune, India with no website.
Revenue model: SaaS subscription ₹3,500–₹15,000/month per client.

## Phase Architecture

### Phase 1 — Chat Memory (COMPLETE)
`ChatService` + `PostgresChatMemoryStore` — persistent chat with Gemini, one session per business.

### Phase 2 — Architect Agent (COMPLETE)
LangGraph4j `StateGraph` with 8 nodes:
```
START → ScrapeBusinessesNode → FilterAndScoreNode
      → ResearchIndustryNode → ResearchCompetitorsNode
      → ResearchSeoNode → ResearchTechStackNode
      → SynthesizeBriefNode → SaveBriefNode → END
```
- Triggered via `POST /api/v2/architect/run`
- Runs async (`@Async`) — returns `runId` immediately
- PostgreSQL checkpointing — resumable if master restarts
- Produces one `ArchitectBrief` per Tier 1 business

### Phase 3 — Coder Agent (IN PROGRESS)
**Master side** (CoderAgentGraph — 2 nodes, graph ends at spawn):
```
START → TaskManagerNode → ContainerSpawnerNode → END
```
**Post-graph lifecycle** (scheduled services, not graph nodes):
- `ContainerMonitorService` — 30s poll, exit detection, failure classification, retry
- `ContainerQueueProcessor` — 30s poll, picks up PENDING/RETRYING when slots open

**Worker side** (discovery-worker module — sequential, not LangGraph4j):
```
FileManifestGeneratorNode → ProjectScaffoldNode → GitHubRepoNode
→ GitCloneNode → BackendGeneratorNode → FrontendGeneratorNode
→ InfraGeneratorNode → DocumentationGeneratorNode
→ BackendValidationNode → FrontendValidationNode
→ GitCommitNode → GitPushNode → PullRequestNode
```

### Phase 4 — Demo & Deployment (NOT STARTED)
- Demo: spawn container → pull from GitHub branch → docker-compose up → expose port
- Production: AWS App Runner (backend) + Vercel (frontend) + RDS database
- Triggered manually via API after client approval

### Phase 5 — Analytics (NOT STARTED)
- Google Analytics 4 per client site
- Razorpay webhook data
- Google Search Console SEO rankings
- Client ROI dashboard

## Container Pool Management

Pool size = `MAX_POOL_SIZE` ENV var (default 2, safe for t3.medium EC2).
Pool state persisted in `container_pool_slot` table (single row, id=1).

```
Task arrives → TaskManagerNode creates ContainerTask (PENDING)
             → ContainerSpawnerNode checks pool
             → slot available → spawn → RUNNING
             → pool full → stay PENDING → ContainerQueueProcessor picks up later

Container exits:
  exit 0 → COMPLETED → slot released → container removed
  exit 1 → read logs → classify failure:
    CODE        → RETRYING (max 3 attempts) → re-queued
    INFRA       → RETRYING (max 3 attempts) → re-queued
    CONFIG_AUTH → FAILED (no retry) → alert human
  timeout (30min) → kill → INFRA failure → RETRYING
```

## Key Design Decisions

**Why not LangGraph4j in the worker?**
Worker is stateless and short-lived. Sequential execution is correct. Checkpointing is via GeneratedFile DB rows, not graph state. If worker dies, master spawns fresh container.

**Why docker-proxy on Mac?**
Mac Docker Desktop runs in a VM — direct socket mounting doesn't work reliably inside containers. `tecnativa/docker-socket-proxy` exposes Docker API over TCP. On EC2 Linux this isn't needed — direct socket mount works natively.

**Why one repo per project?**
Clean separation. Each business gets its own GitHub repo named after the business. If business already exists in DB with a COMPLETED task — create new branch on existing repo instead of new repo.

**Why README.md and claude.md in every commit?**
README.md — human-readable summary for clients and developers.
claude.md — context file for future Claude Code sessions on this project (briefId, tech decisions, deferred items, next steps).

**Why demo separated from code generation?**
Worker ends at PR creation. Demo is on-demand: spawn demo container → pull from GitHub branch → docker-compose up → expose EC2 port. Client sees demo only when you're ready to show them.

**Why ddl-auto=update in master, ddl-auto=none in worker?**
Master owns the schema. Worker only reads/writes data — never touches schema. Prevents accidental schema changes from worker container.

## Common Gotchas

**Docker proxy on Mac** — if `DockerContainerService` fails with `NoHttpResponseException`, check that `docker-proxy` container is running and `APP_DOCKER_HOST=tcp://docker-proxy:2375` is set. `DOCKER_HOST` is a reserved Docker env var and gets overwritten — always use `APP_DOCKER_HOST`.

**Pool slot leak** — if `activeSlots` is stuck above 0 after all containers exited, call `POST /api/v3/containers/cleanup/all`. This calls `poolManager.releaseAllSlots()`.

**gosom status** — gosom uses `"ok"` not `"completed"` as its finished status. `waitForCompletion()` checks for `"ok"` specifically.

**LangGraph4j PostgreSQL saver** — requires `stateSerializer` to be set. Uses `ObjectStreamStateSerializer<AgentState>`. Without it the bean throws NPE on startup.

**Hibernate 7 + Spring Boot 4** — do not use `hypersistence-utils`. Use `@JdbcTypeCode(SqlTypes.JSON)` for all JSONB columns — it's native to Hibernate 7.

**gosom typo** — longitude column in `gmaps_jobs_results` is spelled `longtitude` (extra t). The `GoSomResult` entity maps to this deliberately.

## Business Context

**Target businesses:** Local businesses in Pune, India doing ₹1Cr+ annual revenue with no website.
Identified via Google Maps review count (≥500 for Tier 1) + rating (≥4.0) + no website flag.

**Scoring tiers:**
- TIER_1: reviewCount ≥ 500, rating ≥ 4.0, no website → primary targets
- TIER_2: reviewCount ≥ 200, rating ≥ 3.8, no website → secondary targets
- HAS_WEBSITE: has existing website → excluded for now
- EXCLUDED: below thresholds

**Revenue estimation:** Category-aware model using review rate (1-25% depending on category),
average transaction value per category, and rating multiplier (0.7-1.3x).
Real estate uses 25% review rate (high-stakes purchase → most clients review).

**Subscription pricing:**
- Basic: ₹3,500/month (55% margin)
- Standard: ₹7,000/month (77% margin)
- Premium: ₹13,000/month (88% margin)

Infrastructure cost per active client: ~$17/month (shared RDS + App Runner + Vercel).
